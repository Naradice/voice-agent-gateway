# Android クライアント

`android/` に Gradle プロジェクトがある。プロトコルは `docs/protocol.md`。

| モジュール | 内容 | 検証状況 |
|---|---|---|
| `android/core` | Android に依存しない Kotlin/JVM。プロトコル型、再接続する WebSocket クライアント、読み上げキューと ack 位置の管理、確認への回答の解釈、PTT から読み上げまでを統括する `VoiceController` | **ビルドとテスト済み(39件)**。うち7件は、本物の Gateway(`packages/gateway/src/mock.ts`)を子プロセスで起動して接続する結合テスト |
| `android/app` | 画面(Compose)、フォアグラウンドサービス、`SpeechRecognizer`、`TextToSpeech`、設定の保存。`core` を呼ぶだけの薄い層 | **未ビルド・未実行。** 開発環境から Android SDK(Google の Maven)に届かず、一度もコンパイルしていない |

## core のテスト
```bash
cd android && ./gradlew :core:test      # Node が PATH にあること(結合テストが Gateway のモックを起動する)
```
Android SDK が無い環境では `:app` は自動的に除外される(`settings.gradle.kts`)。

## アプリのビルド・実行
1. Android Studio で `android/` を開く(JDK 17 以上)。`local.properties` が作られると `:app` が含まれる。
2. 実機で実行(`minSdk 26`)。初回に、マイクと通知の許可を求められる。
3. 動作確認には、PC で Android 開発用のモック Gateway を使う(Ollama・Codex 不要):
   ```bash
   npm run gateway:init      # 初回。.env とトークンを作る(VAG_HOST に PC の Tailscale IP が入る)
   npm run gateway:mock
   ```
4. アプリの「設定」で接続先とトークンを設定する。**長いトークンを手で打たない**ために、PC で `npm run gateway:code` を実行して「接続コード」(`ws://<IP>:8787#<トークン>`)を表示し、スマホにコピーして(Tailscale の Taildrop、自分宛てのメッセージなど)、アプリの「接続コードを貼り付け」を押す。接続先とトークンが一度に入る。手で入力する場合は、接続先 `ws://<PCのTailscale IP>:8787` とトークンを入力する。エミュレータなら `ws://10.0.2.2:8787`(VAG_HOST を `0.0.0.0` にはせず、エミュレータ用に別途設定する必要がある点に注意)。
5. 試せる発話(モックの台本): 「こんにちは」(文単位の読み上げ)/「JEPAの実験の件」(確認 → 「1番」と答える)/「busyの確認をCodexで」(使用中の案内)/「Codexの返事を読んで」。

## 設定の入力ミスを防ぐ・確かめる
- **トークンは保存される。** 次に設定を開いたとき、トークン欄は空でよい(「空欄なら保存済みを使う」)。接続先だけ直したいときも、トークンを入れ直さなくてよい。
- **確認コード。** トークンから作る6桁のコード(SHA-256 の先頭6桁)。トークン本体は表示せず、入力したトークンが PC のものと同じかを確かめる。アプリの設定画面(入力中も)とメイン画面に出る。PC では `npm run gateway:code`(または `-- --check`)で同じコードが出る。**一致すれば入力は正しい。** 1文字違えば、まったく違うコードになる。
- **接続テスト。** 保存する前に、その場で接続できるかを確かめる。結果は「接続できました」「届いたがトークンが違う」「届かない(理由つき)」のどれか。テストは専用の接続(`?probe=1`)を使うので、動いている本番の接続を追い出さない。
- **表示/隠す。** トークン欄の表示を切り替えて、目で確認できる。

## つながらないとき
画面の表示で、原因を切り分ける。

| 画面の表示 | 意味 | 対処 |
|---|---|---|
| 「接続先とトークンが未設定です」 | 接続を試みてすらいない | 「設定」で `ws://<PCのTailscale IP>:8787` とトークンを入力する |
| 「マイクの許可がありません」 | 許可がないと、サービスを起動しない | 端末の設定でアプリにマイクを許可する |
| 「接続中…」「未接続(再接続を試行中)」+ 接続エラー | 試みたが届かない | 下の手順で、PC への経路を確かめる |
| 「認証に失敗しました」 | 届いたが、トークンが違う | 下の「認証に失敗するとき」を参照 |
| 「別の端末に接続を置き換えられました」 | 同じトークンで別の接続が来た | 他の端末・アプリを閉じて、アプリを開き直す |

**認証に失敗するとき**(HTTP 401。経路は通っている)
原因は、アプリに入れたトークンの入力ミスか、Gateway が古いトークンで動いていること。確認コードで切り分ける。
1. Gateway のターミナルに、認証失敗のたびに `unauthorized connection attempt` が出る。`presentedFingerprint`(アプリが送ってきたトークンの確認コード)と `expected`(Gateway が期待する確認コード)を比べる。
2. 起動ログの `devices` にも、Gateway が使っているトークンの確認コードが出る。アプリの設定画面の確認コードと比べる。
3. **`.env` を作り直したのに合わない場合:** 以前に `set VAG_DEVICES=…`(PowerShell なら `$env:VAG_DEVICES=…`)で設定した値が、そのウィンドウに残っていると、**環境変数が `.env` より優先される**。起動時に「環境変数が優先されているため使われていません」という警告が出る。cmd なら `set VAG_DEVICES=`(= の右を空に)で消すか、新しいウィンドウで Gateway を起動し直す。
4. 確認コードが一致しないときの入力ミス対策: 「接続コードを貼り付け」を使う(`npm run gateway:code` で表示)。

**PC への経路の確認**(接続エラーが出るとき)
1. PC で Gateway が動いていること。起動ログの `"host"` と `"port"` が、アプリに入力した接続先と一致していること。
2. スマホのブラウザで `http://<PCのTailscale IP>:8787` を開く。**「WebSocket required」と出れば、経路は通っている**(Gateway は HTTP にこう答える)。開けなければ経路の問題。
3. 開けないとき: スマホの Tailscale がつながっているか。PC の Windows ファイアウォールが 8787 を止めていないか。管理者のコマンドプロンプトで、Tailscale からの接続だけを許可する:
   ```bat
   netsh advfirewall firewall add rule name="Voice Agent Gateway" dir=in action=allow protocol=TCP localport=8787 remoteip=100.64.0.0/10 profile=any
   ```
4. 接続先は `ws://`(`http://` や `wss://` ではない)で、ポート番号を含めること。

## 設計上の判断
- **core と app を分けた。** 読み上げの順序・割り込み・ack・再送など、間違えるとデータを失うロジックを、Android なしでテストできるようにするため。app は音声認識・合成・画面の接続だけ。
- **PTT は「タップで開始、もう一度で確定」。** 音声認識は無音検出でも終わる。読み上げ中にタップすると、読み上げを止めて聞く(割り込み。止めた1文は読み終えた扱い)。
- **マイクは PTT のときだけ使う。** 確認要求への回答も、あらためて PTT で受ける(自動で聞き始めない)。聞いている間は読み上げない(音声がマイクに回り込むため)。
- **ack は「読み終えた最大の位置」。** 優先度で順序が入れ替わっても、未読のイベントを巻き込んで Gateway に削除させない。
- **ack の位置は Gateway の識別子(`instanceId`)とセットで保存する。** DB の作り直しや別の Gateway への切り替えで番号が振り直されても、新しいイベントを「読み上げ済み」として捨てない(回帰テストあり)。
- **設定は SharedPreferences。** 設計書の DataStore ではなく同期的に読み書きできる方を選んだ(位置の保存が読み上げのたびに呼ばれるため)。トークンは Android Keystore の鍵で暗号化して保存する。
- **`ws://` を許可している。** Tailscale(WireGuard)で暗号化される前提。公開ネットワークで使うなら `wss://` にして `network_security_config.xml` を厳しくする。
