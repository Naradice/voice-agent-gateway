# 設計書 v0.1 からの変更点

元の設計書(v0.1)との差分を記録する。設計書本体(`docs/design.md`)はこのリポジトリに未収録。

## 2026-10-31

### 日常会話の既定をローカルLLM(Llama)にする
- 変更前(v0.1 §1.2, §6.2): 日常会話は OpenAI API。
- 変更後: **日常会話の既定はローカルLLM**。OpenAI API はオプションのオンライン接続先として残す。
- 実装: `LocalLLMAdapter`(agentType `local`)。Ollama / llama.cpp server / LM Studio など OpenAI 互換の `/v1/chat/completions` を持つ実行基盤を対象にする。履歴の正本は Gateway(SQLite)。`ConversationAdapter` 基底クラスに履歴・中断・永続化を集約し、通信方式だけを派生クラスが持つ。
- 効果: 発話が外部に出ない(§9.3)、API 利用枠に依存しない(Codex と違い上限で止まらない)。

#### この変更で新たに決める必要があること
1. **最新情報の質問(天気など、§5.6)をどう扱うか。** ローカルLLMは検索できない。候補: (a) 検索 API/ツールを Gateway に足す (b) 該当発話だけ OpenAI へ回す(オンライン接続先を使う)(c) 「分からない」と答える。回答を推測させない方針(§5.6)は維持する。
2. **ルーターの宛先名。** 評価データとルールの宛先 `openai` と「ChatGPT」の明示指定は、v0.1 の前提。宛先を `chat`(会話先)のように一般化し、ChatGPT/OpenAI の明示指定を残すか決める。
3. **文脈長。** ローカルモデルは文脈が短い。件数と文字数の両方で履歴を制限している(既定 8000 文字)。実際のモデルの文脈長に合わせて調整する。Ollama の `/v1` では 1 リクエスト単位で文脈長を指定できない可能性があり、既定の文脈長で履歴が黙って切られていないかを実機で確認する。
4. **ルーターのローカルLLM(Phase 0B 方式C/D)も同じ実行基盤を使える。** Embedding も同じ基盤で試せるかを確認する。
